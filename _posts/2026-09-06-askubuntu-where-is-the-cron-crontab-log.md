On Ubuntu, cron does not create a dedicated `/var/log/cron.log` file by default, and modern distributions use **`systemd-journald`** and **`rsyslog`** rather than the legacy `syslog.conf`.

Here is how you can find your cron logs immediately, followed by how to enable a dedicated cron log file if you prefer one.

---

### Method 1: Check System Logs Directly (Fastest)

#### Option A: Using `journalctl` (Recommended for modern Ubuntu)
Because Ubuntu uses `systemd`, all cron executions are captured by the system journal:

```bash
# View all cron logs
sudo journalctl -u cron

# View only the most recent logs and follow them in real time
sudo journalctl -u cron -f

# View cron logs from today only
sudo journalctl -u cron --since today
```

#### Option B: Check `/var/log/syslog`
If your version of Ubuntu runs `rsyslog` (default on Ubuntu 22.04 and earlier), cron events are mixed into the general system log:

```bash
# Filter syslog for cron executions
sudo grep CRON /var/log/syslog

# Follow cron logs in real time
sudo tail -f /var/log/syslog | grep CRON
```

---

### Method 2: Enable a Dedicated `/var/log/cron.log` File

If you want all cron jobs isolated into their own log file (`/var/log/cron.log`), configure `rsyslog`:

1. **Open the rsyslog default configuration file:**
   ```bash
   sudo nano /etc/rsyslog.d/50-default.conf
   ```

2. **Locate this line:**
   ```text
   #cron.*                          /var/log/cron.log
   ```

3. **Uncomment it** by removing the `#` at the beginning:
   ```text
   cron.*                           /var/log/cron.log
   ```

4. **Save and exit** (`Ctrl + O`, `Enter`, then `Ctrl + X`).

5. **Restart the rsyslog service:**
   ```bash
   sudo systemctl restart rsyslog
   ```

From this point forward, all crontab executions will be written to `/var/log/cron.log`.

---

### Important Note: Logging Job Output (STDOUT / STDERR)

The system cron logs only verify that the cron daemon **started** your command. They do not show output, errors, or exit codes generated by the command itself.

To capture the actual output of your job, redirect its output in `sudo crontab -e`:

```cron
0 * * * * /path/to/your/script.sh >> /var/log/myscript.log 2>&1
```

* `>> /var/log/myscript.log` appends standard output to a file.
* `2>&1` redirects standard error to the same file so you catch failures and crash reports.
